# crypto-monitor

Мониторинг, бэктест и paper-торговля криптой по **публичным** API. Торговые ключи не используются.

## Файлы

| Файл | Назначение |
|---|---|
| `monitor.py` | снимок цен с 5 бирж, арбитраж/разброс, алерты (webhook + Telegram), история |
| `strategy.py` | загрузка свечей Binance + бэктест (donchian, ema) с комиссией и слиппеджем |
| `walkforward.py` | вневыборочная проверка: параметры на прошлом, оценка на будущем |
| `paper_trader.py` | виртуальный счёт 1000 USDT, торговля по EMA 50/200, журнал сделок |
| `report.py` | один HTML: живые котировки + кривые капитала |
| `config.json` | пары, источники, правила алертов, кулдаун, Telegram |
| `.env` | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (не коммитить) |
| `data/` | кэш свечей, `snapshots.jsonl`, `alert_state.json`, `paper/` |

## Команды

```bash
python monitor.py                     # один снимок
python monitor.py --quiet             # только алерты (режим cron)
python monitor.py --loop 60           # каждую минуту
python monitor.py --json              # машинный вывод

python strategy.py --symbol BTCUSDT --interval 4h --years 3 --strategy both
python walkforward.py --symbol BTCUSDT --folds 5

python paper_trader.py --init 1000    # сброс виртуального счёта
python paper_trader.py                # тик (идемпотентен на одной свече)
python paper_trader.py --status       # состояние и статистика

python report.py --out report.html

python order_executor.py --balance                     # dry-run подписанного запроса
python order_executor.py --buy 25 --quote              # проверка лимитов, без отправки
python order_executor.py --live --buy 25 --quote       # РЕАЛЬНАЯ заявка на TESTNET
python order_executor.py --flatten                     # закрыть позицию по рынку
```

## Алерты

Правила в `config.json`, проверяются по агрегированной строке (медиана по биржам):

```json
{"symbol": "BTCUSDT", "above": 80000}
{"symbol": "BTCUSDT", "below": 70000}
{"symbol": "ETHUSDT", "change_abs_pct": 5}
{"symbol": "BTCUSDT", "dispersion_pct": 0.5}
```

- Дедупликация: один и тот же алерт не повторяется чаще `alert_cooldown_min` (60 мин). Ключ — правило, а не цена, иначе каждое изменение котировки выглядит «новым» алертом.
- Каналы: stdout (`ALERT: ...`), `webhook_url` (JSON `{"text": ...}`), Telegram.
- Расписание: cron-задание `Крипто-алерты (15 мин)` → `crypto_alert.py` → `monitor.py --quiet`. Пустой вывод = сообщение не отправляется.

**Telegram**: токен от @BotFather и `chat_id` кладутся в `.env`. Написать боту любое сообщение, затем `getUpdates` покажет `chat.id`. Токен в чат и в коммиты не вставлять.

## Как считается

- **Цена**: медиана по Binance / Bybit / OKX / Kraken / Coinbase.
- **Арбитраж %**: `(лучший bid − лучший ask) / медиана` — больше нуля означает возможность купить в одном месте и продать в другом **до** комиссий.
- **Разброс %**: `(макс − мин) / медиана`.
- **Бэктест**: сигнал на закрытии бара `i`, исполнение на закрытии `i+1`; комиссия 0.10% + слиппедж 0.02% за сторону; long-only, без плеча.

## Результаты проверки (окно 2023-11 → 2026-10, 4h)

Полная выборка (in-sample, доверять нельзя):

| Стратегия | Доход | CAGR | MaxDD | Sharpe | Сделок |
|---|---|---|---|---|---|
| EMA 50/200 | +138.2% | +33.6% | −30.4% | 1.06 | 18 |
| EMA 20/50 | +90.5% | +24.0% | −31.1% | 0.85 | 60 |
| Donchian 20/10 | −3.0% | −1.0% | −47.5% | 0.09 | 104 |
| Buy & hold | +124.2% | +30.9% | −53.5% | — | — |

Walk-forward (5 фолдов, параметры выбираются только на прошлом):

| Пара | Склеенный OOS | Buy & hold OOS | Фолдов с плюсом |
|---|---|---|---|
| BTCUSDT | −11.9% | −18.1% | 1 из 5 |
| ETHUSDT | −8.5% | −31.4% | 3 из 5 |
| SOLUSDT | +13.2% | −49.3% | 3 из 5 |

Вывод: на последних ~21 месяцах рынок падал, и трендовый фильтр **срезал убыток** относительно удержания, но сам остался в минусе на BTC/ETH. Это защитный фильтр, а не источник прибыли — поэтому следующий шаг paper-торговля, а не реальные деньги.

## 4. Исполнение ордеров (testnet)

`order_executor.py` ходит только на `https://testnet.binance.vision`. Ключи из `.env`
(`BINANCE_TESTNET_KEY`, `BINANCE_TESTNET_SECRET`), никогда не печатаются и не логируются.

Защита по умолчанию:
- **Без `--live` ордер не отправляется** — только подписанный запрос и проверка лимитов.
- Белый список символов и лимит на одну заявку (`risk.max_notional_usdt`, 50 USDT).
- Каждая заявка пишется в `data/orders.jsonl` с `newClientOrderId`.
- Подпись HMAC-SHA256 сверена с эталонным примером из документации Binance.

## Ограничения — читать обязательно

- Публичные данные ≠ торговля. Ключей API с правом торговли здесь нет вообще.
- Бэктест без funding-ставок, влияния объёма, частичных исполнений и простоев биржи; на истории он оптимистичнее реальности.
- Подбор параметров и проверка на одних данных = переобучение. Для этого есть `walkforward.py`.
- Ничего из этого не является инвестиционной рекомендацией.
