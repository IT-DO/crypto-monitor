```bash
python paper_trader.py --status     # как идёт виртуальная торговля
python report.py --out report.html  # живые котировки + кривые капитала
```

Смотреть на три вещи:

1. **Доход paper против buy & hold.** Стратегия должна отставать по убытку, а не по прибыли.
2. **Просадка.** Если paper-DD уходит ниже −15%, стратегия не готова к реальным деньгам.
3. **Сделки идут.** Если за 3–4 недели ноль сделок — сигнал не появляется, это норма для падающего рынка, но следи, чтобы cron не умер (см. п. 6).

## 3. Как менять алерты и пары

Файл `config.json`.

**Порог по цене:**
```json
{"symbol": "BTCUSDT", "above": 85000}
{"symbol": "BTCUSDT", "below": 72000}
```

**Резкое движение за 24 часа:**
```json
{"symbol": "ETHUSDT", "change_abs_pct": 7}
```

**Расхождение цен между биржами (арбитраж):**
```json
{"symbol": "BTCUSDT", "dispersion_pct": 0.8}
```

Правила:
- `alert_cooldown_min` (60) — сколько минут молчать про то же условие.
- Алерт срабатывает один раз на условие и повторяется не чаще кулдауна: цена выше 80000 будет напоминать раз в час, пока не опустится и не пробьёт снова.
- Новые пары добавляются в `symbols` — но проверь, что пара есть на всех пяти биржах, иначе агрегат будет из меньшего числа источников.

После правки — проверить руками:

```bash
python monitor.py --quiet
```

## 4. Testnet-торговля: ручной режим

Используй его, когда нужно вмешаться руками. Автоматика уже работает (см. п. 4б).

1. Зайти на https://testnet.binance.vision — вход через GitHub.
2. «Generate HMAC-SHA256 Key» → получить Key и Secret. Права: только спот-торговля, **вывод средств не нужен и не должен быть разрешён**.
3. Вписать в `.env` (файл в папке проекта):
   ```
   BINANCE_TESTNET_KEY=...
   BINANCE_TESTNET_SECRET=...
   ```
4. Проверить баланс (dry-run, ничего не отправляет):
   ```bash
   python order_executor.py --balance
   ```
5. Первая реальная заявка на testnet — маленькая:
   ```bash
   python order_executor.py --live --buy 10 --quote
   ```
   В ответе будет ID ордера и его статус.
6. Посмотреть позицию и закрыть:
   ```bash
   python order_executor.py --balance
   python order_executor.py --live --flatten
   ```

Без флага `--live` ничего не отправляется — только проверка лимитов и подписанного запроса.

Лимиты в `config.json` → `risk`:

```json
"risk": {
  "symbol": "BTCUSDT",
  "allowed_symbols": ["BTCUSDT"],
  "max_notional_usdt": 50,
  "max_position_usdt": 100
}
```

Ставить их выше, чем готов потерять, нельзя — скрипт откажется.

## 4б. Авто-бот на testnet — что крутится без тебя

Каждые 4 часа бот смотрит последнюю ЗАКРЫТУЮ 4h-свечу, считает EMA 50/200 и:

- сигнал «лонг», позиции нет → покупает BTC на `risk.alloc_usdt` (сейчас 10 USDT);
- сигнал «вне рынка», позиция есть → продаёт всё, что купил;
- ничего не изменилось → молчит (в чат ничего не приходит).

Проверить руками, что он делает и почему:

```bash
python live_bot.py --status        # сигнал, позиция, реализованный PnL, сделок
python live_bot.py                 # симуляция: что сделал бы, но без ордера
python live_bot.py --live          # исполнить на testnet прямо сейчас
python order_executor.py --live --reconcile   # сверить журнал бота с балансом биржи
```

Остановить автоматику:

- Hermes → `list` → `pause` у задания `a7a700022705`;
- или закрыть позицию руками: `python order_executor.py --live --flatten`.

Правила безопасности, которые уже в коде:
- без `--live` ни один ордер не уходит;
- хост в коде — только `testnet.binance.vision`;
- лимит на заявку `max_notional_usdt` (50), весь контур выделяет 10 USDT;
- `--reset` откажется работать, пока на бирже открыта позиция, — чтобы не потерять учёт;
- каждый ордер пишется в `data/orders.jsonl`, бот — в `data/live/trades.jsonl`;
- счёт и фаусет-средства не трогаются: бот продаёт только то, что купил сам.

Журнал и сверка:

```bash
python order_executor.py --live --reconcile
# журнал бота: 0.00000000 BTC / на бирже: 1.00000000 BTC / базовый остаток: 1.0 (не бота)
# СВЕРКА: расхождений нет
```

Если «СВЕРКА» показала расхождение — значит были ручные сделки или потерялось состояние.
Смотри `data/orders.jsonl` (что бот реально отправлял) и закрывай руками.

## 5. Критерии перехода на реальные деньги

Не переходить, пока **все** пункты не выполнены:

- [ ] Paper-счёт прожил **≥ 8 недель** и сделал **≥ 8 сделок** (меньше — статистики нет).
- [ ] Доход paper **≥ 0** и при этом просадка **не хуже buy & hold**.
- [ ] Testnet-исполнение прошло без сюрпризов: ордера исполняются, `--flatten` закрывает всё.
- [ ] Walk-forward на свежих данных (`python walkforward.py --symbol BTCUSDT --folds 5`) не ушёл в глубокий минус.
- [ ] Ты готов к тому, что стратегия может не заработать: на последних 21 месяцах она была защитной, а не прибыльной.

Если хоть один пункт не выполнен — продолжай paper. Это не потеря времени: цена ошибки здесь — ноль.

## 6. Если что-то молчит

| Симптом | Проверка |
|---|---|
| Нет алертов давно | `python monitor.py --quiet` — пусто значит «нет условий», а не «сломалось» |
| Telegram молчит, а алерт есть | `python monitor.py` — в конце должно быть `ALERT:`; если есть, а в Telegram нет — проверить `.env` и написать боту ещё раз |
| Cron не срабатывает | Hermes: `list` → смотреть `last_run_at` и `last_status`; при `paused` — `resume` |
| Paper перестал тикать | `python paper_trader.py` вручную; в выводе будет либо сделка, либо «свеча уже обработана» |
| Ошибка «нет ключей» | не заполнен `.env`, либо запускаешь `--live` без ключей testnet |
| API биржи лежит | `python monitor.py` покажет `Ошибки источников:` — это не поломка скрипта |

Логи: `data/snapshots.jsonl` (цены), `data/paper/trades.jsonl` (сделки), `data/orders.jsonl` (попытки ордеров), `data/alert_state.json` (когда что алертило).

## 7. Жёсткие правила (не обсуждаются)

1. Ключи API — только в `.env`. Ни в чат, ни в скриншоты, ни в git.
2. Права ключа — **trade**, без **withdrawal**. Отдельный субаккаунт под бота.
3. Первый реальный депозит — сумма, которую не жалко потерять целиком.
4. Плечо не включаем. Шорт не включаем. Пока стратегия не показала себя на paper — вообще ничего не включаем.
5. Если стратегия даёт −20% на реальном счёте — стоп, разбор, а не «отыграюсь».
6. Никаких «догоняющих» сделок руками в обход скрипта: смешанная статистика бесполезна.
